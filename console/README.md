# كونسول إدارة الاشتراكات 💼

لوحة تحكم **المزوّد** (أنت) لمتابعة العيادات العميلة وفوترتها وتحصيل اشتراكاتها.

منفصل تمامًا عن نظام العيادة: **قاعدة بيانات مستقلة وجلسة مستقلة**، لأن بياناته
تجارية ولا يصح أن تختلط ببيانات المرضى. الدخول لأحدهما لا يمنح دخولًا للآخر.

## وضعان للبيع

| | نسخة مستقلة | SaaS |
|---|---|---|
| أين تعمل | استضافة العميل | سيرفرك |
| قاعدة البيانات | قاعدة العميل | قاعدة لكل عيادة على سيرفرك |
| العنوان | نطاق العميل | `اسم-العيادة.نطاقك` |
| التركيب | يدوي (`install.php`) | تلقائي بضغطة أو بتسجيل ذاتي |
| التحديث | العميل يسحبه بنفسه | تحدّث مرة، وترقّي كل القواعد بزر |
| ربط الاشتراك | نبضة يومية برمز | مقروء مباشرة من قاعدة التحكم |

الوضعان يعملان معًا من نفس الكونسول: عملاء بنسخ مستقلة وعملاء على SaaS جنبًا إلى جنب.

## داشبوردان لا واحد

| | مَن يفتحها | ماذا يرى |
|---|---|---|
| `clinic/` | الطبيب وفريقه | مرضاه ومواعيده وحساباته |
| `console/` | أنت | عملاؤك واشتراكاتهم وتحصيلك |

## المميزات

- **سجل العيادات**: بيانات كل عميل، خطته، حالته (تجريبي / مشترك / موقوف / ملغي)،
  وتاريخ انتهاء اشتراكه.
- **خطط اشتراك**: شهري / ربع سنوي / سنوي أو ما تشاء، مع حساب الشهري المكافئ.
- **فواتير**: ترقيم تلقائي `INV-YYYY-0001`، استحقاق، ومتابعة المسدد والمتبقي.
- **تحصيل بثلاث وسائل**: كاش، إنستا باي، وباي موب أونلاين.
- **تجديد تلقائي للاشتراك** عند اكتمال سداد الفاتورة — لا تعديل يدوي للتواريخ.
- **رابط سداد للعميل** يُرسل بواتساب، يفتحه ويدفع بدون حساب.
- **نبضة من كل نسخة**: إصدارها وعدد مرضاها وآخر اتصال، وتنبيه بالعيادات الصامتة.
- **لوحة تحكم**: الدخل الشهري المتكرر (MRR)، تحصيل الشهر، المستحق، ومن يحتاج تجديدًا.
- **سجل نشاط** بكل حدث ومَن نفّذه.

## التثبيت

1. أنشئ **قاعدة بيانات جديدة** من cPanel (غير قواعد العيادات).
2. ارفع مجلد `console/` واستدعِ `install.php` من المتصفح.
3. **احذف `install.php`** بعد نجاح التثبيت.
4. من **الإعدادات** اكتب رابط الكونسول — بدونه لا تعمل روابط السداد.

## وسائل الدفع

### كاش
تسجّل الدفعة يدويًا من صفحة الفاتورة، وتُحتسب مؤكدة فورًا.

### إنستا باي
تكتب عنوانك (‎`اسمك@instapay`‎) في الإعدادات فيظهر للعميل في صفحة السداد.
سجّل الدفعة وعلّم **«بانتظار التأكيد»**، وبعد أن تتأكد من وصول المبلغ لحسابك
أكّدها من صفحة المدفوعات — عندها فقط يُجدَّد الاشتراك.

### باي موب (أونلاين)
من لوحة باي موب (`Settings → Account Info`) انسخ:
`API Key` · `Integration ID` · `iFrame ID` · `HMAC Secret` إلى إعدادات الكونسول.

ثم في `Developers → Payment Integrations` اضبط على قناة التحصيل:

| الحقل | القيمة |
|---|---|
| Transaction Processed Callback | `https://…/console/paymob_callback.php` |
| Transaction Response Callback | `https://…/console/paymob_return.php` |

**التأكيد لا يعتمد على عودة العميل للمتصفح إطلاقًا**، بل على الإشعار الموقّع
بـ HMAC-SHA512 القادم من خوادم باي موب. الإشعار بتوقيع غير صالح يُرفض ويُسجَّل،
والإشعار المكرر لا يجدّد الاشتراك مرتين.

> ⚠️ التكامل مكتوب على تدفّق Accept الموثّق ومُختبَر بإشعارات محاكاة (توقيع صحيح
> ومزوّر ومكرر). **أجرِ عملية حقيقية بمبلغ صغير** بمفاتيحك قبل تشغيلها مع العملاء.

## ربط نسخة عيادة بالكونسول

افتح ملف العيادة في الكونسول وانسخ السطرين إلى `clinic/inc/config.php` عندها:

```php
define('LICENSE_URL', 'https://…/console/ping.php');
define('LICENSE_TOKEN', '…');
```

فترسل النسخة حالتها مرة يوميًا، ويظهر لمدير العيادة تنبيه قبل انتهاء الاشتراك
مع رابط التجديد.

**النسخ المباعة كرخصة دائمة لا تُعرَّف فيها هذه الثوابت، فلا يحدث أي اتصال خارجي.**

### ما لا يفعله الربط — عن قصد

- **لا يقفل النظام أبدًا.** بيانات المرضى ملك العيادة، وأقصى ما يحدث عند انتهاء
  الاشتراك تنبيه ظاهر. حجب سجل طبي عن طبيب خطر مهني وقانوني لا يستحق ثمن اشتراك.
- **انقطاع الاتصال لا يعني انتهاء الاشتراك.** لو تعطّل الكونسول أو الشبكة تُبقي
  النسخة آخر حالة معروفة وتكمل عملها — لا تتعطل عيادة بسبب مشكلة عندنا.
- **لا يرسل أي بيانات مرضى** — فقط: الإصدار، وعدد المرضى، وعدد المستخدمين النشطين.

## تشغيل وضع SaaS 🏢

**لماذا قاعدة لكل عيادة وليس عمود `tenant_id`؟** لأن العزل يقع عند **الاتصال** لا
عند كل استعلام. في نموذج `tenant_id` يكفي استعلام واحد يُنسى فيه الفلتر لتظهر
بيانات مرضى عيادة لعيادة أخرى — وهذا في نظام طبي ليس خطأً يُصلَح لاحقًا. هنا لا
يوجد فلتر أصلًا يُنسى.

### المتطلبات

SaaS يحتاج **VPS** لا استضافة مشتركة: الأخيرة تحدّ عدد قواعد البيانات ولا تتيح
نطاقات فرعية تلقائية.

1. **DNS**: سجل `*` (wildcard) يوجّه `*.نطاقك` لسيرفرك، وشهادة SSL شاملة.
2. **مستخدم MySQL واحد** لكل القواعد:
   ```sql
   CREATE USER 'app'@'localhost' IDENTIFIED BY '...';
   GRANT ALL PRIVILEGES ON `clinic\_%`.* TO 'app'@'localhost';
   GRANT ALL PRIVILEGES ON `console`.*  TO 'app'@'localhost';
   GRANT CREATE, DROP ON *.* TO 'app'@'localhost';
   ```
   لا تُحفظ كلمات مرور لكل عيادة على حدة — مستخدم واحد وبادئة موحّدة.
3. **`clinic/inc/config.php`**: فعّل قسم SaaS (انظر `config.sample.php`).
4. **إعدادات الكونسول**: النطاق الأساسي، بادئة القواعد، أيام التجربة.

### إنشاء العيادات

- **يدويًا**: `عيادات SaaS ← + عيادة جديدة` — تُنشأ القاعدة وتُجهَّز وتبدأ التجربة.
- **ذاتيًا**: فعّل «فتح التسجيل الذاتي» فيصبح `signup.php` صفحة تسجيل عامة
  ينشئ منها الطبيب عيادته بنفسه خلال ثوانٍ.

الإنشاء **ذرّي**: لو فشل تجهيز القاعدة تُحذف القاعدة ويُحذف صف العيادة، فلا تبقى
عيادة نصف مجهّزة.

### بعد كل تحديث للنظام

`عيادات SaaS ← ⬆ ترقية كل القواعد` — تمر الترقية على كل عيادة وتعرض نتيجة كل
واحدة على حدة. عيادة متأخرة في السكيما تعني أخطاء عند أول استخدام.

### مهام مجدولة

```cron
0 18 * * *  /usr/bin/php /path/to/clinic/cron/reminders_all.php
0  3 * * *  /usr/bin/php /path/to/console/cli/backup_all.php /path/to/backups 14
```

`reminders_all.php` يمر على كل العيادات النشطة، وفشل عيادة لا يوقف البقية.
`backup_all.php` يأخذ نسخة مستقلة لكل قاعدة، فاستعادة عيادة واحدة لا تمس غيرها.

### عند انتهاء الاشتراك

بعد مهلة السماح تتوقف **الإضافة والتعديل فقط**: العيادة تظل ترى كل بياناتها
وتصدّرها وتأخذ نسخة احتياطية منها. حجب سجل طبي عن طبيب ضغطٌ غير مقبول، والمنع
مطبَّق من نقطة واحدة على السيرفر فلا يُتجاوز بإخفاء زر.

## الأمان

- كل الاستعلامات بعبارات مُجهَّزة (Prepared Statements).
- كل نموذج POST محمي بـ CSRF، ويشمل ذلك صفحة السداد العامة.
- روابط السداد برموز عشوائية (48 خانة) لا أرقام متسلسلة، فلا يمكن تصفّح فواتير
  الآخرين بالتخمين.
- رمز النبضة يُقبل عبر POST فقط حتى لا يُسجَّل في سجلات السيرفر.
- `inc/` محمي بـ `.htaccess`، وكلمات المرور مُجزّأة بـ `password_hash`.
- مفاتيح باي موب السرية لا تُعرض بعد حفظها ولا تُمسح بترك الحقل فارغًا.
