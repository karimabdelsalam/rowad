# منصة Pclinic على لارافيل — قيد الترحيل 🚧

ترحيل تدريجي للنظام من PHP native إلى Laravel 13، **بدون توقف البيع ولا التطوير**.

## لماذا التدرّج وليس إعادة الكتابة

النظام الحالي (`../clinic` و`../console`) شغّال ومُختبَر عمليًا. إعادة كتابته دفعة
واحدة تعني شهورًا بلا ميزات، وخطر كسر شيئين لا يُغتفر كسرهما: **عزل بيانات
العيادات** و**منطق الفلوس**. فالخطة:

1. **السكيما تبقى مطابقة بالحرف.** الترحيل يستبدل طبقة التطبيق فقط، والبيانات لا
   تُلمس — فالنسختان تعملان على نفس القاعدة، والتراجع ممكن في أي لحظة.
2. **الكونسول أولًا** (4,550 سطرًا، بلا بيانات مرضى)، ثم تطبيق العيادة.
3. **الاختبارات تُكتب أثناء النقل لا بعده**: نصف السلوك القديم في اختبار، ثم
   نثبت أن الجديد يحققه. هذا يحوّل «شكله شغال» إلى إثبات.
4. النظام الحالي يظل يبيع ويعمل طوال الفترة.

## ما تبقّى

- باقي صفحات الكونسول: العيادات، الفواتير، المدفوعات، الخطط، المستخدمون،
  الإعدادات، عيادات SaaS، وصفحات السداد العامة
- `ProvisioningService` و`WhatsAppService`
- أوامر artisan بديلة عن `cli/billing_run.php` و`backup_all.php`
- ثم تطبيق العيادة (12,000 سطر) بعد استقرار الكونسول

## الروابط غير المنقولة بعد

القائمة الجانبية وأزرار اللوحة تظهر فقط إن كان مسار الصفحة مسجّلًا
(`Route::has`). فالتطبيق **يعمل عند كل خطوة** أثناء الترحيل بدل أن ينكسر حتى
تكتمل كل الصفحات.

## التشغيل محليًا

```bash
composer install
cp .env.example .env && php artisan key:generate
php artisan migrate
php artisan test
```

## الاختبارات

تعمل على **MySQL حقيقي** لا SQLite في الذاكرة، لأن المنطق يعتمد على `ENUM`
و`lockForUpdate` وسلوك المفاتيح الأجنبية — واختبار على محرك مختلف عن الإنتاج
يعطي طمأنينة كاذبة.

أهمها يغطي ما يمكن أن يضيّع فلوسًا: الدفع الجزئي لا يمدّ الاشتراك، الدفعة
المعلّقة لا تُحتسب، السداد الكامل يمدّ **مرة واحدة** مهما أُعيد الحساب، إلغاء
التأكيد يعكس المدّ، تجديد اشتراك منتهٍ يبدأ من اليوم بينما الساري يحتفظ بأيامه،
وتوقيع باي موب يُرفض إن زُوِّر أو وُقِّع بمفتاح آخر أو عُدِّل أي حقل موقَّع.
